# Results: Flux Memory, mem0, Letta and Honcho on LongMemEval-S (n=100) and LoCoMo

Status: results of one run per arm, on 2026-10-03. Every number below is regenerated by `python3 analysis/report.py` from `results-public/`; `python3 analysis/report.py --check` fails if this file is out of date. The preregistration is the README of this repository (sections "Held equal", "Statistics", "LoCoMo", "Stop rules"), committed before the run.

## Key findings, stated plainly

<!-- GEN:key_findings -->
On LoCoMo (all five categories, the figure in the qa summaries), the Honcho chat arm scored **85.6%**. That is above every Flux arm (flux_public 74.9%, flux_evidence 74.3%) and above full context (79.1%). On categories 1 to 4 only (the preregistered headline, n=1540) the figures are: honcho_chat 83.8%, full_context 77.6%, flux_public 70.6%, flux_evidence 70.5%, honcho_retrieval 67.7%, mem0 66.0%, letta 61.2%, closed_book 15.0%.

On LongMemEval-S (n=100): full_context 94%, flux_evidence 91%, flux_public 84%, honcho_retrieval 82%, honcho_chat 81%, letta 81%, mem0 75%, closed_book 10%.
<!-- /GEN:key_findings -->

- **Honcho's chat arm scored 85.6% on LoCoMo (all five categories), above every Flux arm (74.9% and 74.3%) and above full context (79.1%).** On categories 1 to 4 it scored 83.8% against 70.6% and 70.5% for the Flux arms and 77.6% for full context. The paired tests below put the gap to Flux at about 11 points (all categories) and 13 points (categories 1 to 4), with intervals far from zero.
- What `honcho_chat` is: the question is sent to Honcho's own chat (dialectic) endpoint, `POST /workspaces/<id>/chat` with `reasoning_level: "low"`, on the workspace Honcho built from the conversation. Honcho's dialectic agent searches that workspace and writes an answer. In this run Honcho was configured (`compose/honcho/config.toml`) so that every dialectic level calls `deepseek-flash` through our metering proxy; it is the same model family as our reader, not a Honcho-hosted model. That answer text is then given to our reader (`deepseek-flash`, temperature 0, the LoCoMo reader prompt) as a single context item, and the reader's output is what the judge grades. The retrieval arm (`honcho_retrieval`) is different: it takes up to 9 retrieved conclusions per peer from `peer.context` with the question as the search query, capped at 20 items and 16 KiB like every other arm, and our reader answers from that list. So `honcho_chat` is an answering agent that reads the whole workspace through its own tools, not a retrieval list, and it is not held to the 16 KiB / 20-item context budget that the retrieval arms share. It is reported separately for that reason. The README says so before the run.
- On LongMemEval-S with n=100, differences of a few points between flux_public (84%), honcho_retrieval (82%), honcho_chat (81%) and letta (81%) are within noise: the paired interval against flux_public includes zero for each of them and no Holm-adjusted p-value is below 0.05 (table in "Paired comparisons"). flux_public against mem0 (+9 points, interval +0 to +18, Holm p 0.37) is also not separated. Only the comparisons with full_context and closed_book are clearly separated from flux_public.
- No arm is called best here, and no claim of superiority is made by this report.

## Paired comparisons

For LoCoMo the questions fall in 10 conversations, so a conversation-clustered bootstrap (resampling whole conversations) is also given; the item bootstrap and the McNemar test treat questions as independent and are too optimistic. Holm correction across the 7 comparisons made for each Flux arm within an item set. The README preregistered comparisons against `flux_public` only; the `flux_evidence` rows and the clustered interval are additions.

## Deviations from the preregistration

1. **Bootstrap seed and comparison set.** The README preregisters seed 0, comparisons against `flux_public` only, and Holm across them. This report uses seed 20261003 as instructed, adds `flux_evidence` as a second reference arm, and adds a conversation-clustered interval for LoCoMo. `analysis/analyze.py` (seed 0) is unchanged and still available.
2. **LoCoMo headline set.** The preregistered overall figure is categories 1 to 4. The run's own summary files (and the figures first quoted from them) are over all five categories. Both are reported.
3. **Spend cap.** Raised from USD 55 to USD 75 before the run (disclosed in the README). `COST.md` estimates were made against 55. Actual spend USD 34.3685, just below the low estimate of 34.88 (high estimate 53.85). Honcho LongMemEval ingest cost USD 8.77 against an estimate of 9.30 to 15.00; mem0 LongMemEval ingest cost USD 4.16 against 8.10.
4. **Staged runs for Honcho, mem0, Letta.** Each system was first run on the first 10 haystacks (3 conversations on LoCoMo), checked, then continued into the same results directory for the rest. This is the preregistered stop-rule check, not a rerun. The Honcho cost rule did not fire (`honcho-rule-lme.out`: "ok (10 haystacks seen)"; `honcho-rule-locomo.out`: "ok (3 haystacks seen)"). The files named `honcho-rule-*` in the run directory are those check outputs. No arm was restarted or re-rolled: `progress.log` shows one start and one qa stage per arm and benchmark.
5. **Errors and empty answers, all scored wrong.** LongMemEval: 0 errors in every arm; empty answers: full_context 1, flux_evidence 1, flux_public 1, honcho_retrieval 1, letta 2, mem0 1. LoCoMo (all categories): errors flux_public 2, flux_evidence 1, letta 2, closed_book 1 (flux_public and closed_book: `IncompleteRead` from the answering call; flux_evidence and letta: `ValueError`, which the runner raises when the judge reply is not exactly CORRECT or WRONG; none retried because the run's single resume step is triggered only by a non-zero exit); empty answers flux_public 7, flux_evidence 3, honcho_retrieval 3, mem0 7, letta 21. Letta's 21 empty answers are 1.4% of its 1,540 judged questions and lower its score; the cause was not investigated.
6. **Dropped ingest items.** Honcho dropped 1 of 49,080 turns and Letta 1 of 49,081 on LongMemEval (0.002%, far below the 2% stop rule). No other arm dropped any, and no unit failed.
7. **Honcho arms share one ingest** (`--arms ctx,chat`, as the README states). Query-time LLM spend for both arms is booked together under `honcho_retrieval`; it is attributed to the chat arm in `COST.md` by inference from the driver, because the proxy log that would separate them was not copied.
8. **Kit version on the run host.** `progress.log` records "kit archive" rather than a git commit for the copy that ran. Checked after the run by hashing the kit files on the run host: they are identical to commit `a9a65be` (the 75 USD cap test). The one later commit before the results, `ad2bc16`, only fills vendor list prices in the cost inputs and was not part of the run.
9. **Judge cost units.** Judge USD uses the gpt-5-mini list price set in `run.sh`, also for the GPT-6 Astra preference grades.
10. **Promised but not reported.** Retrieval latency percentiles and empty-retrieval share (README "Statistics") need `retrieved.jsonl`, which was not copied because it contains dataset text. Operations tables use the ingest records only.
11. **Unchanged known limits.** Flux in-process (disclosed), Letta 0.16.8 while newer releases existed, mem0 extraction non-determinism (one run per arm), embedder client library versions not those of the earlier private runs.

## What this does and does not show

It shows, for this reader, these judges, these drivers and this single run per arm:

- On LoCoMo, Honcho's chat endpoint, used as an answering agent, scored higher than every other arm tested, including full context and both Flux arms, on every aggregate (all categories and categories 1 to 4), with intervals that do not overlap Flux's. This is for the aggregates. On category 5 (string rule) honcho_chat (91.7%) is below mem0 (95.3%) and honcho_retrieval (94.8%) and above both Flux arms (89.5%, 87.7%).
- On LoCoMo, with a retrieval list of equal size handed to the same reader, `flux_public` and `flux_evidence` scored about the same as each other and, on categories 1 to 4, about 3 points above `honcho_retrieval` (conversation-clustered interval above zero; Holm-adjusted p 0.07 and 0.10, so not clear on the preregistered test), about 4 to 5 above mem0 and about 9 above Letta.
- On LongMemEval-S with n=100, only large gaps are resolvable. flux_public, honcho_retrieval, honcho_chat and letta are not separated from each other; mem0 is not separated from flux_public after Holm correction. Full context scored above flux_public, and flux_evidence is higher than flux_public by 7 points (McNemar p 0.065, interval +1 to +14; not separated on the preregistered Holm rule). Per question type, cells hold 6 to 27 questions; per-type differences are not tested and should not be read as findings.

It does not show:

- That any system is best in general, or best for a product use. One reader, one judge family, one sample of LongMemEval-S, one run per arm.
- That the Honcho chat result is retrieval quality. The arm uses an LLM agent with its own search tools over the whole workspace and a second LLM pass by our reader, and is not held to the context budget the retrieval arms share. Cost per query is also different (see `COST.md`).
- That the Flux arms measured here equal the hosted API: they ran in-process.
- That the numbers transfer to other readers, other judges, other embedders or longer horizons. The judge is an LLM and was not audited item by item.
- Anything about differences below the intervals shown. LoCoMo's 10 conversations are few clusters; the clustered intervals are wider than the item intervals for several comparisons.
- Anything about the cost of the hosted products beyond what `COST.md` states.

## Exploratory arm added after the main run: flux_reason

This section is separate from everything above. The arm `flux_reason` was designed on 2026-10-04, **after** the main results were known, and preregistered in [PREREG-ADDENDUM-flux_reason.md](PREREG-ADDENDUM-flux_reason.md) (committed and pushed before the arm's first paid call; the prompt `prompts/flux_reason_prompt.txt` has sha256 `e52763d7923ce70d44df52b3fd37f5fbee5bd07f0c1e1fc6d6a56e62ede04e4f`). One run, no re-rolls, failures scored wrong, same question sets. It ran on the main run's host.

**What this arm shows and does not show.** On LoCoMo categories 1 to 4, one reasoning pass over the stored `flux_evidence` retrieval raised accuracy from 70.5% to 73.3% (+2.9 points; item interval +0.6 to +5.1, conversation-clustered interval -0.2 to +6.2, so the gain is small and not clearly separated from zero once the 10 conversations are treated as the units), and closed about a fifth of the 13.4-point gap to `honcho_chat` (83.8%); it ended 10.5 points below `honcho_chat`, so by the threshold stated before the run (within 5.0 points) it does not close most of the gap. The gain was uneven: temporal questions (category 2) rose from 43.9% to 72.3% and multi-hop (category 1) moved little (54.3% to 56.0%), while open-domain (category 3) fell from 55.2% to 39.6% and single-hop (category 4) fell from 87.8% to 83.4%; adversarial category 5 rose from 87.7% to 95.5% (string rule; it was reported separately and is not part of the verdict). On LongMemEval-S (n=100) it scored 80%, 11 points below `flux_evidence` (91%, paired p 0.001), 4 below `flux_public` and 1 below `honcho_chat`, so there the note step lost information that the full 32 KiB context kept; n=100 can only resolve large gaps. What it does not show: it reuses the stored `flux_evidence` retrieval, so any evidence that retrieval missed stays missing; it is a single reasoning pass with no multi-step search or query rewriting, which is what the Honcho dialectic agent does with its own tools, so it is not a test of an agentic Flux; Flux ran in-process, not through the hosted API; the prompt was written after the main results were known (one prompt, not tuned; no variants were tried), and temperature and max tokens could not be matched to Honcho's unrecorded values; one run, so the run-to-run noise of the reasoning pass is not measured; and the category-level pattern was not investigated, so the reasons for the category 3 and category 4 drops are not known. It does not show that a better reasoning prompt, a stronger reasoning model or an agentic loop over Flux memory would or would not close the gap.
